# Складність алгоритмів

Дві програми можуть давати однакові правильні відповіді, але одна працює соту частку секунди, а інша — три години. На олімпіаді друга отримає вердикт TLE на великих тестах. Як ще до написання коду зрозуміти, чи встигне програма? Для цього оцінюють **складність алгоритму**.

> [!NOTE] У цьому уроці
> - як порахувати кількість дій програми;
> - запис O(…) і основні класи складності;
> - головна таблиця: які обмеження — який алгоритм;
> - що таке log n і звідки він береться;
> - як пришвидшити розв’язок на прикладах.

## Скільки дій робить програма

Сучасний комп’ютер виконує приблизно **10⁸ простих дій за секунду**: додавань, порівнянь, звертань до масиву. Тому оцінюють, як кількість дій залежить від розміру вхідних даних `n`:

```cpp
// один цикл до n — приблизно n дій
for (int i = 0; i < n; i++) sum += a[i];

// два вкладені цикли до n — приблизно n² дій
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        if (a[i] + a[j] == k) cnt++;

// ділимо навпіл, доки не дійдемо до 1 — приблизно log₂ n дій
while (n > 1) n /= 2;
```

## Запис O(…)

Точна кількість дій не важлива: 3n + 5 чи 2n — різниця в кілька разів. Важливо, **як швидко** вона росте зі збільшенням `n`. Тому складність записують у вигляді **O(…)** («о велике від…»), відкидаючи сталі множники і менші доданки:

- 3n + 5 → **O(n)**;
- n²/2 + 100n → **O(n²)**;
- 20 → **O(1)** — кількість дій не залежить від `n`.

| Складність | Назва | Приклад |
| --- | --- | --- |
| O(1) | стала | формула, звертання до елемента масиву |
| O(log n) | логарифмічна | бінарний пошук, швидкий степінь |
| O(√n) | корінь | перебір дільників до √n |
| O(n) | лінійна | один прохід по масиву |
| O(n log n) | — | сортування `sort` |
| O(n²) | квадратична | усі пари елементів |
| O(n³) | кубічна | три вкладені цикли |
| O(2ⁿ) | експоненційна | перебір усіх підмножин |
| O(n!) | факторіальна | перебір усіх перестановок |

## Головна таблиця олімпіадника

Підстав найбільше `n` з умови у формулу складності і порівняй з 10⁸. Для обмеження часу в 1 секунду зазвичай виходить так:

| Обмеження на `n` | Допустима складність |
| --- | --- |
| n ≤ 10 | O(n!) |
| n ≤ 20 | O(2ⁿ) |
| n ≤ 500 | O(n³) |
| n ≤ 5000 | O(n²) |
| n ≤ 10⁶ | O(n log n) |
| n ≤ 10⁸ | O(n) |
| n ≤ 10¹⁸ | O(√n) лише до 10¹⁴, а далі — O(log n) або O(1) |

> [!IMPORTANT]
> Це працює і в зворотний бік: обмеження **підказують ідею**. Якщо `n ≤ 20` — швидше за все, автори задумали перебір. Якщо `n ≤ 2·10⁵` — шукай розв’язок за O(n log n): сортування, бінарний пошук, `set`.

## Що таке log n

log₂ n — це скільки разів треба поділити `n` навпіл, щоб дійти до 1. Логарифм росте **дуже повільно**:

| n | 1000 | 10⁶ | 10⁹ | 10¹⁸ |
| --- | --- | --- | --- | --- |
| log₂ n | ≈ 10 | ≈ 20 | ≈ 30 | ≈ 60 |

Тому алгоритм за O(log n) для мільярда робить лише 30 кроків, а O(n log n) для мільйона — близько 20 мільйонів дій, що цілком встигає.

## Як пришвидшувати: три приклади

**1. Формула замість циклу.** Сума чисел від 1 до `n` — це `n · (n + 1) / 2`. Цикл за O(n) для `n = 10¹⁸` не закінчиться ніколи, а формула — O(1).

**2. До кореня замість до `n`.** Пошук дільників до √n замість до `n` (урок про `break`): для `n = 10¹²` — мільйон кроків замість трильйона.

**3. Розумніший підхід замість перебору пар.** Задача: скільки пар однакових чисел у масиві з `n ≤ 10⁵` елементів? Перебір пар — 5·10⁹ дій, задовго. А якщо порахувати, скільки разів трапляється кожне значення (через `map` чи сортування), то значення, що трапилося `c` разів, дає `c · (c − 1) / 2` пар. Разом — O(n log n).

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    map<int, long long> cnt;
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        cnt[x]++;
    }
    long long pairs = 0;
    for (auto p : cnt) pairs += p.second * (p.second - 1) / 2;
    cout << pairs << "\n";
    return 0;
}
```

```input
6
5 1 5 5 2 1
```

```output
4
```

(Три п’ятірки дають 3 пари, дві одиниці — ще одну.)

## Пам’ять

Пам’ять теж обмежена — зазвичай 128–256 МБ. Оцінюй розмір масивів: `int` — 4 байти, `long long` — 8 байтів.

- масив з 10⁶ `int` — 4 МБ, нормально;
- таблиця 5000 × 5000 `int` — 100 МБ, на межі;
- масив з 10⁹ елементів — неможливо.

```exercise
id: pair-products
title: Сума попарних добутків
level: 3
=== statement
Дано `n` чисел. Знайди суму добутків усіх пар `a[i] · a[j]`, де `i < j`. Наприклад, для чисел 1, 2, 3 це 1·2 + 1·3 + 2·3 = 11.
=== input
У першому рядку — число `n` (1 ≤ n ≤ 10⁵). У другому — `n` цілих чисел, кожне за модулем не більше 10⁴.
=== output
Сума попарних добутків.
=== example
3
1 2 3
---
11
=== example
1
5
---
0
=== test
2
-3 4
---
-12
=== test
4
10000 10000 10000 10000
---
600000000
=== test
5
1 -1 1 -1 1
---
-2
=== hint
Розкрий квадрат суми: (a₁ + a₂ + … + aₙ)² = (a₁² + … + aₙ²) + 2 · (сума попарних добутків).
=== hint
Отже, відповідь = (S² − Q) / 2, де S — сума чисел, Q — сума їхніх квадратів. Це O(n) замість O(n²).
=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long s = 0, q = 0;
    for (int i = 0; i < n; i++) {
        long long x;
        cin >> x;
        s += x;
        q += x * x;
    }
    cout << (s * s - q) / 2 << "\n";
    return 0;
}
```

## Коротко

- Комп’ютер виконує ≈10⁸ простих дій за секунду; підстав найбільше `n` у складність і порівняй.
- O(…) показує, як росте кількість дій: сталі множники і менші доданки відкидають.
- n ≤ 20 — перебір, n ≤ 5000 — O(n²), n ≤ 10⁶ — O(n log n), більше — O(n) чи формула.
- log₂ n дуже малий: 30 для мільярда.
- Пришвидшують формулами, перебором до кореня, підрахунком частот, сортуванням.
