# Жадібні алгоритми

**Жадібний алгоритм** на кожному кроці робить вибір, який здається найкращим **зараз**, не думаючи про майбутнє. Наприклад, видаючи решту, касир спершу бере найбільшу купюру, яка поміщається в суму. Іноді такий підхід дає найкращу відповідь, а іноді — ні. Головне вміння — розрізняти ці випадки.

> [!NOTE] У цьому уроці
> - ідея жадібного алгоритму на прикладі видачі решти;
> - коли жадібність помиляється;
> - класичні жадібні задачі: найбільше справ, найменше очікування, найбільше покупок;
> - як переконатися, що жадібний алгоритм правильний.

## Видача решти

Потрібно видати суму `n` гривень найменшою кількістю купюр і монет номіналом 1, 2, 5, 10, 20, 50, 100, 200, 500. Жадібна стратегія: щоразу беремо найбільший номінал, що не перевищує залишок.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> values = {500, 200, 100, 50, 20, 10, 5, 2, 1};
    int count = 0;
    for (int v : values) {
        count += n / v;    // скільки купюр цього номіналу
        n %= v;            // скільки залишилося видати
    }
    cout << count << "\n";
    return 0;
}
```

```input
288
```

```output
7
```

Простежимо для 288: беремо 200 (залишок 88), 50 (38), 20 (18), 10 (8), 5 (3), 2 (1) і 1 (0) — разом 7 купюр і монет. Зверни увагу на прийом `count += n / v; n %= v;`: замість того щоб віднімати номінал по одному разу, ми одразу беремо стільки купюр, скільки поміщається.

## Коли жадібність помиляється

Для українських грошей жадібний алгоритм дає найменшу кількість купюр. Але так буває не завжди. Нехай є монети 1, 3 і 4, і треба набрати 6:

- жадібно: 4 + 1 + 1 — **три** монети;
- оптимально: 3 + 3 — **дві** монети.

Перший вибір (взяти найбільшу монету 4) виявився помилкою, яку вже не виправиш. Такі задачі розв’язують динамічним програмуванням (наступні уроки).

> [!IMPORTANT]
> Жадібний алгоритм потребує доведення або хоча б ретельної перевірки. Простий спосіб: напиши повний перебір для маленьких даних і порівняй відповіді на сотнях випадкових тестів.

## Найбільше справ: задача про заявки

Є `n` заходів, кожен із часом початку і кінця. В одній аудиторії не можна проводити два заходи одночасно. Скільки найбільше заходів можна провести?

Жадібна ідея: **вибирати захід, що закінчується найраніше**, серед тих, що не перетинаються з уже вибраними. Чим раніше звільняється аудиторія, тим більше місця для інших заходів.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<pair<int, int>> ev(n);           // (кінець, початок) — щоб сортувати за кінцем
    for (auto &e : ev) cin >> e.second >> e.first;
    sort(ev.begin(), ev.end());
    int count = 0, freeAt = INT_MIN;        // коли аудиторія звільняється
    for (auto &e : ev) {
        if (e.second >= freeAt) {           // захід починається, коли аудиторія вже вільна
            count++;
            freeAt = e.first;
        }
    }
    cout << count << "\n";
    return 0;
}
```

```input
5
1 4
3 5
0 6
5 7
8 9
```

```output
3
```

Вибрано заходи (1, 4), (5, 7), (8, 9). Тут вважається, що захід, який починається в момент закінчення попереднього, не перетинається з ним.

**Чому це правильно?** Нехай є найкращий розклад. Замінимо в ньому перший захід на той, що закінчується найраніше, — розклад не зіпсується, бо новий захід звільняє аудиторію не пізніше. Далі те саме міркування для решти. Це приклад **доведення обміном**: найкращий розв’язок можна поступово перетворити на жадібний, не погіршуючи його.

## Найменше очікування

До лікаря черга з `n` пацієнтів, `i`-й пацієнт займе `t[i]` хвилин. У якому порядку приймати пацієнтів, щоб **сумарний час очікування** був найменшим?

Відповідь: **від найкоротших прийомів до найдовших**. Тривалість першого прийому чекають усі наступні пацієнти, тому на початку вигідно ставити короткі. Достатньо відсортувати `t` за зростанням і просумувати, скільки чекав кожен.

## Найбільше покупок

Є бюджет `B` і ціни `n` товарів. Скільки найбільше товарів можна купити? Очевидно — купувати **найдешевші**: відсортувати ціни і брати по черзі, доки вистачає грошей.

Зверни увагу: майже всі жадібні розв’язки починаються з **сортування** за правильно вибраною ознакою. Уся складність — зрозуміти, за якою.

title: Решта

=== statement
Касир видає суму `n` гривень купюрами й монетами номіналом 1, 2, 5, 10, 20, 50, 100, 200 і 500 гривень. Яка найменша кількість купюр і монет йому знадобиться?
=== input
Одне ціле число `n` (1 ≤ n ≤ 10⁹).
=== output
Найменша кількість купюр і монет.
=== example

---

=== example

---

=== test

---

=== test
1000000000
---
2000000
=== test
888

=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    long long n;
    cin >> n;
    vector<long long> values = {500, 200, 100, 50, 20, 10, 5, 2, 1};

    for (long long v : values) {
        count += n / v;
        n %= v;

У Марійки є `B` гривень. У магазині `n` різних іграшок, кожна в одному примірнику. Яку найбільшу кількість іграшок вона може купити?
=== input

=== example

=== test

=== test
3 100000000000000
1000000000 1000000000 1000000000
---

3 3 3 3
---

=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    long long B;
    cin >> n >> B;
    vector<long long> p(n);
    for (auto &x : p) cin >> x;
    sort(p.begin(), p.end());
    int count = 0;
    for (long long x : p) {
        if (x > B) break;
        B -= x;
        count++;
    }
    cout << count << "\n";
    return 0;

id: doctor

=== statement
До лікаря прийшли `n` пацієнтів; прийом `i`-го триває `t[i]` хвилин. Лікар приймає їх по одному в будь-якому порядку. Час очікування пацієнта — це сума тривалостей усіх прийомів перед ним. Знайди найменший можливий сумарний час очікування всіх пацієнтів.

---

20
=== hint
Приймай пацієнтів від найкоротшого прийому до найдовшого. Пацієнт чекає суму всіх попередніх прийомів.
=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> t(n);
    for (auto &x : t) cin >> x;
    sort(t.begin(), t.end());
    long long total = 0, elapsed = 0;
    for (long long x : t) {
        total += elapsed;
        elapsed += x;
    }
    cout << total << "\n";
    return 0;
}

```exercise
id: refuel
title: Подорож із заправками
level: 3
=== statement
Автомобіль їде з точки 0 у точку `L` по прямій. З повним баком він проїжджає `d` кілометрів. Уздовж дороги є `n` заправок у точках `x[1] < x[2] < … < x[n]`. На старті бак повний, на заправці бак заправляють повністю. Яку найменшу кількість заправок треба зробити, щоб доїхати? Якщо доїхати неможливо, виведи `-1`.
=== input
У першому рядку — числа `L`, `d`, `n` (1 ≤ L, d ≤ 10⁹, 0 ≤ n ≤ 10⁵). У другому — `n` чисел `x[i]` у порядку зростання (0 < x[i] < L). Якщо `n = 0`, другого рядка немає.
=== output
Найменша кількість заправок або `-1`.
=== example
10 4 3
3 6 8
---
2
=== example
10 3 2
2 7
---
-1
=== test
5 5 0
---
0
=== test
5 4 0
---
-1
=== test
10 2 5
2 4 6 8 9
---
4
=== test
100 60 3
10 50 70
---
1
=== hint
Їдь якомога далі на поточному баку: заправляйся лише на останній заправці, до якої ще можна доїхати.
=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    long long L, d;
    int n;
    cin >> L >> d >> n;
    vector<long long> x(n);
    for (auto &v : x) cin >> v;
    long long reach = d;     // докуди можна доїхати з поточним баком
    int stops = 0, i = 0;
    while (reach < L) {
        long long best = -1;  // остання заправка, до якої дістаємося
        while (i < n && x[i] <= reach) {
            best = x[i];
            i++;
        }
        if (best == -1) {     // жодної нової заправки в межах досяжності
            cout << -1 << "\n";
            return 0;
        }
        stops++;
        reach = best + d;
    }
    cout << stops << "\n";
    return 0;
}
```

## Коротко

- Жадібний алгоритм на кожному кроці робить найкращий вибір зараз і не переглядає його.
- Він працює не завжди (монети 1, 3, 4) — потрібне доведення чи перевірка перебором.
- Класика: найбільше заходів — за найранішим кінцем; найменше очікування — від коротких до довгих; найбільше покупок — від дешевих.
- Більшість жадібних розв’язків починаються з сортування за правильною ознакою.
