# Як розв’язувати олімпіадні задачі

Ти вже знаєш основи мови C++. Тепер — про те, як ці знання перетворюються на бали. Олімпіадна задача — це не лише код: треба уважно прочитати умову, придумати ідею, врахувати обмеження і перевірити розв’язок на «підступних» тестах. У цьому уроці — план дій, шаблон програми і поради для олімпіади.

> [!NOTE] У цьому уроці
> - з чого складається умова задачі;
> - план роботи над задачею;
> - шаблон олімпіадної програми і швидке введення-виведення;
> - що означають вердикти і як шукати помилки;
> - крайні випадки, часткові розв’язки, план на 4 години олімпіади.

## Будова умови

Типова олімпіадна задача складається з таких частин:

- **легенда** — історія, в яку «загорнуто» математичну суть задачі;
- **вхідні дані** — що і в якому форматі отримує програма;
- **вихідні дані** — що і в якому форматі вона має вивести;
- **обмеження** — межі для чисел (наприклад, `1 ≤ n ≤ 10⁵`), а також обмеження часу (наприклад, 1 секунда) і пам’яті (наприклад, 256 МБ);
- **приклади** — кілька тестів з відповідями;
- іноді **примітки** і **система оцінювання** (скільки балів за які тести).

> [!IMPORTANT]
> Обмеження — найцінніша підказка в умові. Вони кажуть, які типи даних потрібні (чи вміщується відповідь в `int`) і наскільки швидким має бути алгоритм. Як це оцінювати, розберемо в наступному уроці.

## План роботи над задачею

1. **Прочитай умову двічі.** Випиши, що дано і що треба знайти. Зверни увагу на дрібниці: «включно» чи «строго», нумерація з 0 чи з 1, що виводити, якщо відповіді немає.
2. **Розв’яжи приклади вручну.** Якщо відповідь у прикладі не збігається з твоїм розумінням — ти неправильно зрозумів умову.
3. **Подивись на обмеження.** Оціни, чи вистачить `int`, і яка складність алгоритму допустима.
4. **Придумай ідею** і перевір її на прикладах і на кількох власних маленьких тестах.
5. **Напиши код.** Невеликими частинами, з зрозумілими іменами змінних.
6. **Протестуй:** приклади з умови, крайні випадки (див. нижче), великі значення.
7. **Здай розв’язок** і переконайся, що файл має правильну назву.

## Шаблон програми

На олімпіадах зазвичай використовують такий шаблон:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    long long sum = 0;
    for (int i = 0; i < n; i++) {
        long long x;
        cin >> x;
        sum += x;
    }
    cout << sum << "\n";
    return 0;
}
```

```input
3
1000000000 1000000000 1000000000
```

```output
3000000000
```

Що тут нового:

- `#include <bits/stdc++.h>` підключає **всю** стандартну бібліотеку одним рядком: `iostream`, `vector`, `algorithm`, `set`, `map`, `cmath` і решту. Більше не треба згадувати, яку бібліотеку підключити. Цей рядок працює з компілятором GCC, який стоїть на олімпіадах і в Code::Blocks.
- `ios::sync_with_stdio(false);` і `cin.tie(nullptr);` прискорюють `cin` і `cout` у кілька разів. Це важливо, коли треба прочитати сотні тисяч чисел.

> [!WARNING]
> Після цих двох рядків не змішуй `cin`/`cout` з `scanf`/`printf` — вивід може перемішатися. І пиши `"\n"` замість `endl`: `endl` щоразу примусово «виштовхує» виведення, і на великих даних це помітно гальмує програму.

## Вердикти і що з ними робити

| Вердикт | Що сталося | Де шукати помилку |
| --- | --- | --- |
| WA — Wrong Answer | неправильна відповідь | неправильно зрозуміла умова, крайні випадки, переповнення `int`, неправильний формат виведення |
| TLE — Time Limit Exceeded | задовго працює | надто повільний алгоритм, нескінченний цикл, повільне введення-виведення |
| RE — Runtime Error | аварійна зупинка | вихід за межі масиву, ділення на нуль, надто глибока рекурсія |
| MLE — Memory Limit Exceeded | забагато пам’яті | надто великі масиви |
| CE — Compilation Error | не скомпілювалося | вибрано не ту мову чи компілятор, синтаксична помилка |

## Крайні випадки

Більшість втрачених балів — через випадки, про які автор розв’язку не подумав. Перед здачею перевір програму на таких тестах:

- **найменші значення:** `n = 1`, числа дорівнюють 0 або 1;
- **найбільші значення:** чи не буде переповнення, чи вкладеться програма в час;
- **однакові значення:** усі числа рівні;
- **від’ємні числа**, якщо умова їх дозволяє (пам’ятаєш про `%` для від’ємних?);
- **відповіді не існує:** що програма виведе тоді?

## Часткові розв’язки

На олімпіаді бали нараховують за кожен пройдений тест (або групу тестів). Тому навіть неповний розв’язок цінний.

- Якщо не знаєш швидкого розв’язку, напиши **повільний, але правильний** — наприклад, перебір. Він пройде тести з маленькими `n` і принесе частину балів.
- Якщо в умові описано підзадачі (наприклад, «у 30 % тестів n ≤ 100»), розв’яжи спершу найпростішу.
- Повільний розв’язок корисний і для перевірки швидкого: якщо на маленьких тестах відповіді обох збігаються, швидкий, найімовірніше, правильний. Такий спосіб перевірки називають **стрес-тестуванням**.

## Файли і назви

Уважно читай, звідки програма читає дані і куди виводить. Найчастіше це **стандартне введення і виведення** (клавіатура й екран) — як в усіх наших програмах. Але деякі олімпіади вимагають читати з файлу і писати у файл. Тоді на початку `main` додають:

```cpp
freopen("input.txt", "r", stdin);
freopen("output.txt", "w", stdout);
```

і далі програма працює з `cin` і `cout` як звичайно.

> [!TIP]
> В умовах районних олімпіад часто вказано **назву програми**, наприклад: «Програма `Racing2024` читає з пристрою стандартного введення…». Збережи розв’язок саме з такою назвою: `Racing2024.cpp`.

## План на олімпіаду

1. **Перші 15–20 хвилин** прочитай усі задачі. Оціни, яка найлегша.
2. **Почни з найлегшої** задачі і доведи її до кінця, з перевіркою крайніх випадків. Повністю розв’язана легка задача цінніша за недописану складну.
3. **Не застрягай.** Якщо понад 40 хвилин немає жодного руху вперед — переходь до іншої задачі, а до цієї повернешся пізніше.
4. Для задач без повного розв’язку напиши **перебір** чи розв’язок для простих випадків.
5. **Регулярно зберігай** файли. За 15 хвилин до кінця перевір, що всі розв’язки збережено з правильними назвами.

## Перевір себе

```quiz
? Що дає рядок `#include <bits/stdc++.h>`?
- Прискорює роботу програми
+ Підключає всю стандартну бібліотеку одразу
- Дозволяє не писати `using namespace std;`
: Це «все в одному»: `iostream`, `vector`, `algorithm` і решта бібліотек.

? Програма отримала вердикт RE. Що з цього може бути причиною?
- Програма вивела зайвий пробіл
+ Звернення до `a[n]` у масиві з `n` елементів
- Повільний алгоритм
: Вихід за межі масиву, ділення на нуль чи надто глибока рекурсія призводять до аварійної зупинки.

? Чому на олімпіадах замість `endl` пишуть `"\n"`?
+ `endl` щоразу примусово виводить накопичений текст і гальмує програму
- `"\n"` не переходить на новий рядок
- `endl` не працює з `bits/stdc++.h`
: Обидва варіанти переходять на новий рядок, але `"\n"` значно швидший.

? Ти не знаєш швидкого розв’язку задачі. Що робити?
- Нічого не здавати
+ Написати повільний, але правильний розв’язок — він набере частину балів
- Здати програму, що виводить відповідь з першого прикладу
: Повільний розв’язок пройде тести з маленькими даними. Це гарантовані бали.

? Що з цього — крайній випадок, який варто перевірити?
- Приклад з умови
+ `n = 1` або всі числа однакові
- Тест, який ти вже успішно перевірив
: Найменші й найбільші значення, однакові числа, «немає відповіді» — типові пастки.
```

## Практика

```exercise
id: theatre-square
title: Плитка для площі
level: 1
=== statement
Прямокутну площу розміром `n × m` метрів вирішили вимостити квадратною плиткою зі стороною `a` метрів. Плитку не можна різати, але можна виходити за межі площі; сторони плиток мають бути паралельні сторонам площі. Яка найменша кількість плиток потрібна, щоб повністю покрити площу?
=== input
Три натуральних числа `n`, `m` і `a` (1 ≤ n, m, a ≤ 10⁹).
=== output
Найменша кількість плиток.
=== example
6 6 4
---
4
=== test
1 1 1
---
1
=== test
1000000000 1000000000 1
---
1000000000000000000
=== test
1 1000000000 1000000000
---
1
=== test
7 3 2
---
8
=== hint
Уздовж кожної сторони потрібна кількість плиток, округлена вгору: `(n + a - 1) / a`. Кількість плиток — добуток двох таких чисел.
=== hint
Подивись на обмеження: відповідь може сягати 10¹⁸.
=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    long long n, m, a;
    cin >> n >> m >> a;
    cout << ((n + a - 1) / a) * ((m + a - 1) / a) << "\n";
    return 0;
}
```

```exercise
id: fast-sum
title: Багато чисел
level: 2
=== statement
Дано `n` чисел. Виведи суму тих із них, що діляться на 3, і кількість таких чисел. Чисел може бути до мільйона, тож скористайся олімпіадним шаблоном зі швидким введенням-виведенням.
=== input
У першому рядку — число `n` (1 ≤ n ≤ 10⁶). У другому — `n` цілих чисел, кожне за модулем не більше 10⁹.
=== output
Два числа через пробіл: сума і кількість чисел, кратних 3.
=== example
5
3 7 -6 9 10
---
6 3
=== example
2
1 2
---
0 0
=== test
1
0
---
0 1
=== test
4
999999999 999999999 999999999 999999999
---
3999999996 4
=== test
3
-3 -9 1
---
-12 2
=== hint
Перевірка `x % 3 == 0` правильна і для від’ємних чисел: остача в них буде 0, −1 або −2.
=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    long long sum = 0;
    int count = 0;
    for (int i = 0; i < n; i++) {
        long long x;
        cin >> x;
        if (x % 3 == 0) {
            sum += x;
            count++;
        }
    }
    cout << sum << " " << count << "\n";
    return 0;
}
```

## Коротко

- Умова: легенда, вхідні й вихідні дані, обмеження, приклади. Обмеження підказують типи й алгоритм.
- План: прочитати двічі → розв’язати приклади вручну → оцінити обмеження → ідея → код → тести.
- Шаблон: `#include <bits/stdc++.h>`, `ios::sync_with_stdio(false); cin.tie(nullptr);`, `"\n"` замість `endl`.
- WA — логіка і крайні випадки, TLE — швидкість, RE — межі масивів і ділення на нуль.
- Повільний правильний розв’язок краще, ніж нічого; на олімпіаді починай з найлегшої задачі.
