# Бінарний пошук

Гра: я загадав число від 1 до 100, ти називаєш числа, а я відповідаю «більше» чи «менше». Найкраща стратегія — щоразу називати середину проміжку, що залишився: тоді кожна відповідь відкидає половину варіантів, і число вгадується не більше ніж за 7 спроб. Це і є **бінарний пошук** — один із найважливіших алгоритмів в олімпіадному програмуванні.

> [!NOTE] У цьому уроці
> - бінарний пошук у відсортованому масиві;
> - готові функції `lower_bound`, `upper_bound`, `binary_search`;
> - бінарний пошук відповіді;
> - як не помилитися з межами.

## Пошук у відсортованому масиві

Шукаємо у відсортованому масиві **перший елемент, не менший за `x`**. Тримаємо межі `lo` і `hi` і стежимо, щоб виконувалися дві умови:

- `a[lo] < x` (усе на позиції `lo` і лівіше — точно менше за `x`);
- `a[hi] >= x` (на позиції `hi` — вже не менше).

Для зручності уявімо, що `a[-1]` — «мінус нескінченність», а `a[n]` — «плюс нескінченність». Тоді на початку `lo = -1`, `hi = n`. Ділимо проміжок навпіл, доки межі не стануть сусідніми:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> a = {2, 5, 8, 8, 12, 17};
    int n = a.size();
    int x = 8;
    int lo = -1, hi = n;
    while (hi - lo > 1) {
        int mid = (lo + hi) / 2;
        if (a[mid] < x) lo = mid;   // mid разом з усім ліворуч — менші за x
        else hi = mid;              // a[mid] >= x — відповідь не правіше mid
    }
    cout << hi << "\n";             // перша позиція з a[hi] >= x
    return 0;
}
```

```output
2
```

Перша вісімка стоїть на позиції 2. Якщо `hi == n` або `a[hi] != x`, — числа `x` у масиві немає.

На кожному кроці проміжок зменшується вдвічі, тож кроків — близько log₂ n: для мільйона елементів це 20 порівнянь замість мільйона.

> [!IMPORTANT]
> Бінарний пошук працює лише у **відсортованому** масиві. Якщо дані невідсортовані — спершу `sort`.

## Готові функції

У C++ бінарний пошук уже реалізовано:

| Функція | Що повертає |
| --- | --- |
| `lower_bound(a.begin(), a.end(), x)` | ітератор на перший елемент **≥ x** |
| `upper_bound(a.begin(), a.end(), x)` | ітератор на перший елемент **> x** |
| `binary_search(a.begin(), a.end(), x)` | `true`, якщо `x` є в масиві |

Індекс отримують відніманням `a.begin()`. А ще з їхньою допомогою легко рахувати:

- скільки елементів **менші** за `x` — це індекс `lower_bound`;
- скільки елементів **не більші** за `x` — індекс `upper_bound`;
- скільки разів трапляється `x` — різниця `upper_bound − lower_bound`.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> a = {2, 5, 8, 8, 12, 17};
    int lb = lower_bound(a.begin(), a.end(), 8) - a.begin();
    int ub = upper_bound(a.begin(), a.end(), 8) - a.begin();
    cout << lb << " " << ub << " " << ub - lb << "\n";
    cout << binary_search(a.begin(), a.end(), 9) << "\n";
    return 0;
}
```

```output
2 4 2
0
```

## Бінарний пошук відповіді

Найсильніше застосування бінарного пошуку — шукати не елемент масиву, а **саму відповідь задачі**.

Приклад. Потрібно розмістити `n` прямокутних дипломів розміром `w × h` на квадратній дошці (дипломи не можна повертати). Яка найменша сторона дошки?

Знайти сторону напряму складно. Зате легко **перевірити**, чи підходить дошка зі стороною `s`: в один ряд уміщується `s / w` дипломів, рядів — `s / h`, тож дипломів — `(s / w) · (s / h)`. І головне: якщо дошка зі стороною `s` підходить, то будь-яка більша теж підходить. Така властивість називається **монотонністю**:

| s | 1 | 2 | … | 8 | 9 | 10 | … |
| --- | --- | --- | --- | --- | --- | --- | --- |
| підходить? | ні | ні | … | ні | так | так | … |

Нам треба знайти межу між «ні» і «так» — і це той самий бінарний пошук:

```cpp
#include <bits/stdc++.h>
using namespace std;

long long w, h, n;

bool fits(long long s) {
    return (s / w) * (s / h) >= n;
}

int main() {
    cin >> w >> h >> n;
    long long lo = 0;                     // точно не підходить
    long long hi = max(w, h) * n;         // точно підходить: усі дипломи в один ряд
    while (hi - lo > 1) {
        long long mid = (lo + hi) / 2;
        if (fits(mid)) hi = mid;
        else lo = mid;
    }
    cout << hi << "\n";
    return 0;
}
```

```input
2 3 10
```

```output
9
```

Перевір: дошка 9 × 9 вміщує 4 · 3 = 12 дипломів, а 8 × 8 — лише 4 · 2 = 8.

Схема бінарного пошуку відповіді:

1. Напиши функцію `check(x)`: чи підходить `x`.
2. Переконайся, що вона монотонна: після першого «так» усі наступні — теж «так».
3. Вибери `lo`, для якого точно «ні», і `hi`, для якого точно «так».
4. Ділимо навпіл, доки `hi − lo > 1`. Відповідь — `hi`.

> [!CAUTION]
> Стеж за переповненням у `check`: тут `(s / w) * (s / h)` може бути дуже великим. У задачі з дипломами `hi` не перевищує 10¹⁸, але добуток двох часток може сягати 10³⁶! Обмеж `hi` розумнішою оцінкою або порівнюй обережно, наприклад: якщо `s / w >= n`, то вже підходить.

## Бінарний пошук для дробових чисел

Якщо відповідь — дробове число, межі не стануть «сусідніми». Тоді просто роблять фіксовану кількість кроків, наприклад 100: кожен крок удвічі зменшує похибку, і після 100 кроків вона мізерна.

```cpp
double lo = 0, hi = 1e9;
for (int it = 0; it < 100; it++) {
    double mid = (lo + hi) / 2;
    if (check(mid)) hi = mid; else lo = mid;
}
```

+ 2

- 4

+ `upper_bound − lower_bound`
- `binary_search(...)`
: Від першого елемента > x відняти перший елемент ≥ x.

? Яка властивість потрібна функції `check`, щоб шукати відповідь бінарним пошуком?
- Вона має повертати число

- Вона має працювати за O(1)

```exercise
id: contains
title: Чи є число
level: 1
=== statement
Дано масив і `q` запитів. Для кожного запиту `x` виведи `YES`, якщо число `x` є в масиві, і `NO` — якщо немає.
=== input
У першому рядку — числа `n` і `q` (1 ≤ n, q ≤ 10⁵). У другому — `n` цілих чисел (не обов’язково відсортованих). У третьому — `q` чисел-запитів. Усі числа за модулем не більші 10⁹.
=== output
`q` рядків: `YES` або `NO`.
=== example
5 3
8 2 5 12 5
5 7 12
---
YES
NO
YES
=== test
1 2
1000000000
1000000000 -1000000000
---
YES
NO
=== test
3 1
1 2 3
4
---
NO
=== hint
Відсортуй масив один раз, а потім для кожного запиту виклич `binary_search`. Перегляд усього масиву для кожного запиту — це 10¹⁰ дій.
=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    vector<int> a(n);
    for (auto &x : a) cin >> x;
    sort(a.begin(), a.end());
    while (q--) {
        int x;
        cin >> x;
        cout << (binary_search(a.begin(), a.end(), x) ? "YES" : "NO") << "\n";
    }
    return 0;
}
```

```exercise
id: diplomas
title: Дипломи
level: 2
=== statement
Треба розмістити `n` однакових прямокутних дипломів розміром `w × h` на квадратній дошці так, щоб дипломи не перекривалися і не виходили за межі дошки. Повертати дипломи не можна. Яка найменша сторона дошки?
=== input
Три натуральних числа `w`, `h`, `n` (1 ≤ w, h, n ≤ 10⁹).
=== output
Найменша сторона дошки.
=== example
2 3 10
---
9
=== test
1 1 1
---
1
=== test
1 1 1000000000
---
31623
=== test
1000000000 1000000000 1000000000
---
31623000000000
=== test
1 1000000000 1
---
1000000000
=== hint
Перевірка для сторони `s`: в один ряд уміщується `inRow = s / w` дипломів, а рядів — `s / h`. Не перемножуй ці числа: добуток може не вміститися навіть у `long long`. Натомість порахуй, скільки рядів потрібно: `(n + inRow - 1) / inRow`, і порівняй із `s / h`.
=== hint
Верхня межа: дошка зі стороною `max(w, h) · n` точно підходить (усі дипломи в один ряд). Це до 10¹⁸ — вміщується в `long long`.
=== solution
#include <bits/stdc++.h>
using namespace std;

long long w, h, n;

bool fits(long long s) {
    long long inRow = s / w, rows = s / h;
    if (inRow == 0 || rows == 0) return false;
    if (inRow >= n) return true;
    long long needRows = (n + inRow - 1) / inRow;
    return rows >= needRows;
}

int main() {
    cin >> w >> h >> n;
    long long lo = 0, hi = max(w, h) * n;
    while (hi - lo > 1) {
        long long mid = lo + (hi - lo) / 2;
        if (fits(mid)) hi = mid;
        else lo = mid;
    }
    cout << hi << "\n";
    return 0;
}
```

```exercise
id: split-array
title: Розподіл завдань
level: 3
=== statement
Учитель має перевірити `n` робіт, що лежать стосом у певному порядку; на `i`-ту роботу потрібно `a[i]` хвилин. Він хоче розподілити роботи між `k` днями: кожного дня перевіряє кілька робіт **поспіль** зі стосу (можливо, жодної). Як розподілити, щоб найдовший робочий день був якомога коротшим? Виведи його тривалість.
=== input
У першому рядку — числа `n` і `k` (1 ≤ k ≤ n ≤ 10⁵). У другому — `n` натуральних чисел, кожне не більше 10⁴.
=== output
Найменша можлива тривалість найдовшого дня.
=== example
5 2
7 2 5 10 8
---
18
=== example
4 4
1 2 3 4
---
4
=== test
1 1
100
---
100
=== test
5 1
1 1 1 1 1
---
5
=== test
6 3
1 1 1 1 1 10
---
10
=== hint
Бінарний пошук відповіді: для тривалості дня `T` жадібно перевір, чи вистачить `k` днів — додавай роботи в поточний день, доки сума не перевищить `T`, а тоді починай новий день.
=== hint
Тривалість не може бути меншою за найдовшу окрему роботу. Межі пошуку: `lo = max(a) − 1` (не підходить), `hi = сума всіх a` (підходить).
=== solution
#include <bits/stdc++.h>
using namespace std;

int n, k;
vector<long long> a;

bool enough(long long T) {
    int days = 1;
    long long cur = 0;
    for (long long x : a) {
        if (x > T) return false;
        if (cur + x > T) {
            days++;
            cur = 0;
        }
        cur += x;
    }
    return days <= k;
}

int main() {
    cin >> n >> k;
    a.resize(n);
    long long total = 0, mx = 0;
    for (auto &x : a) {
        cin >> x;
        total += x;
        mx = max(mx, x);
    }
    long long lo = mx - 1, hi = total;
    while (hi - lo > 1) {
        long long mid = (lo + hi) / 2;
        if (enough(mid)) hi = mid;
        else lo = mid;
    }
    cout << hi << "\n";
    return 0;
}
```

## Коротко

- Бінарний пошук ділить проміжок навпіл і працює за O(log n), але лише у відсортованих даних.
- Тримай інваріант: `lo` — «ні», `hi` — «так»; цикл `while (hi − lo > 1)`; відповідь — `hi`.
- `lower_bound` — перший ≥ x, `upper_bound` — перший > x, `binary_search` — чи є x.
- Бінарний пошук відповіді: монотонна перевірка `check(x)` + ділення навпіл.
- Для дробових відповідей — фіксована кількість кроків, наприклад 100.
