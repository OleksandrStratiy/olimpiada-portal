# Динамічне програмування

**Динамічне програмування** (ДП) — це спосіб розв’язувати задачу через відповіді на менші підзадачі, обчислюючи кожну підзадачу лише **один раз** і запам’ятовуючи результат. Це одна з найважливіших ідей олімпіадного програмування: на обласних і всеукраїнських олімпіадах задачі на ДП трапляються майже щороку.

> [!NOTE] У цьому уроці
> - від повільної рекурсії до швидкого ДП на прикладі чисел Фібоначчі;
> - рецепт ДП: стан, перехід, база, відповідь;
> - класичні задачі: сходинки, жабка, шляхи в таблиці, монети, найдовша зростаюча підпослідовність, рюкзак.

## Від рекурсії до таблиці

Згадай числа Фібоначчі: F(n) = F(n − 1) + F(n − 2). Наївна рекурсія обчислює ті самі значення мільйони разів. Але кожне F(i) залежить лише від двох попередніх — то обчислимо їх **по черзі, від менших до більших**, і запишемо в масив:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> f(n + 1);
    f[1] = 1;
    if (n >= 2) f[2] = 1;
    for (int i = 3; i <= n; i++) {
        f[i] = f[i - 1] + f[i - 2];
    }
    cout << f[n] << "\n";
    return 0;
}
```

```input
90
```

```output
2880067194370816120
```

90 кроків замість ~10¹⁸ рекурсивних викликів. Це і є динамічне програмування: **кожна підзадача розв’язується один раз, а результат зберігається в таблиці**.

## Рецепт ДП

Розв’язуючи задачу динамічним програмуванням, відповідай на чотири питання:

1. **Стан.** Що означає `dp[i]` (або `dp[i][j]`)? Це має бути відповідь на меншу версію задачі. Формулюй словами: «`dp[i]` — кількість способів дійти до сходинки `i`».
2. **Перехід.** Як обчислити `dp[i]` через уже відомі значення?
3. **База.** Які значення відомі одразу (зазвичай для найменших `i`)?
4. **Відповідь і порядок.** Де в таблиці відповідь і в якому порядку заповнювати таблицю, щоб потрібні значення вже були пораховані?

## Сходинки

Скількома способами можна піднятися на `n`-ту сходинку, якщо за крок можна піднятися на 1 або на 2 сходинки?

- **Стан:** `dp[i]` — кількість способів потрапити на сходинку `i`.
- **Перехід:** на сходинку `i` можна потрапити або з `i − 1`, або з `i − 2`. Отже, `dp[i] = dp[i − 1] + dp[i − 2]`.
- **База:** `dp[0] = 1` (стоїмо внизу — один спосіб), `dp[1] = 1`.
- **Відповідь:** `dp[n]`.

Знову Фібоначчі! Динамічне програмування часто виявляє, що різні на вигляд задачі мають однакову будову.

## Жабка: найменша вартість

Жабка стоїть на першому з `n` каменів. Висота `i`-го каменя — `h[i]`. Жабка стрибає на наступний камінь або через один, і стрибок з каменя `i` на камінь `j` коштує `|h[i] − h[j]|` енергії. Яка найменша сумарна витрата, щоб дістатися останнього каменя?

- **Стан:** `dp[i]` — найменша витрата, щоб дістатися каменя `i`.
- **Перехід:** на камінь `i` жабка стрибнула або з `i − 1`, або з `i − 2`, і вибираємо дешевший варіант:
  `dp[i] = min(dp[i − 1] + |h[i] − h[i − 1]|, dp[i − 2] + |h[i] − h[i − 2]|)`.
- **База:** `dp[1] = 0`.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> h(n + 1), dp(n + 1);
    for (int i = 1; i <= n; i++) cin >> h[i];
    dp[1] = 0;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + abs(h[i] - h[i - 1]);
        if (i >= 3) dp[i] = min(dp[i], dp[i - 2] + abs(h[i] - h[i - 2]));
    }
    cout << dp[n] << "\n";
    return 0;
}
```

```input
4
10 30 40 20
```

```output
30
```

Найкращий шлях: 1 → 2 → 4 (витрати 20 + 10 = 30).

> [!IMPORTANT]
> Жадібний вибір «стрибати туди, куди зараз дешевше» тут може помилитися. ДП не вгадує, а порівнює **всі** способи потрапити в кожен стан — тому воно надійне.

## Шляхи в таблиці

Робот стоїть у лівій верхній клітинці таблиці `n × m` і може ходити лише вправо або вниз. Скількома способами він дійде до правої нижньої клітинки?

- **Стан:** `dp[i][j]` — кількість шляхів до клітинки (i, j).
- **Перехід:** у клітинку (i, j) можна прийти зверху або зліва: `dp[i][j] = dp[i − 1][j] + dp[i][j − 1]`.
- **База:** `dp[0][0] = 1`.
- **Порядок:** заповнюємо рядок за рядком, зліва направо — тоді верхня і ліва клітинки вже пораховані.

Якщо в деяких клітинках стоять перешкоди, для них просто `dp[i][j] = 0`. А якщо кожна клітинка має «вартість» і треба знайти найдешевший шлях — замість суми беремо мінімум.

## Монети: коли жадібність не працює

Пам’ятаєш монети 1, 3, 4 і суму 6 з уроку про жадібні алгоритми? ДП розв’язує цю задачу правильно для будь-яких номіналів.

- **Стан:** `dp[s]` — найменша кількість монет, щоб набрати суму `s`.
- **Перехід:** остання монета — якась `c`; тоді перед нею була сума `s − c`: `dp[s] = min(dp[s − c] + 1)` по всіх монетах `c ≤ s`.
- **База:** `dp[0] = 0`. Недосяжні суми позначаємо «нескінченністю».

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> coins = {1, 3, 4};
    int S = 6;
    const int INF = 1e9;
    vector<int> dp(S + 1, INF);
    dp[0] = 0;
    for (int s = 1; s <= S; s++) {
        for (int c : coins) {
            if (c <= s && dp[s - c] != INF) dp[s] = min(dp[s], dp[s - c] + 1);
        }
    }
    cout << dp[S] << "\n";
    return 0;
}
```

```output
2
```

## Найдовша зростаюча підпослідовність

Дано послідовність чисел. Треба викреслити якомога менше чисел, щоб решта йшла строго за зростанням. Інакше кажучи, знайти найдовшу зростаючу підпослідовність (числа не обов’язково стоять поруч).

- **Стан:** `dp[i]` — довжина найдовшої зростаючої підпослідовності, що **закінчується** на `a[i]`.
- **Перехід:** перед `a[i]` у такій підпослідовності стоїть якесь `a[j]` з `j < i` і `a[j] < a[i]`: `dp[i] = 1 + max(dp[j])`. Якщо такого `j` немає — `dp[i] = 1`.
- **Відповідь:** найбільше з усіх `dp[i]`.

Складність — O(n²), що підходить для `n` до кількох тисяч.

## Рюкзак

У рюкзак вміщується вага `W`. Є `n` предметів, у кожного вага `w[i]` і цінність `v[i]`. Яку найбільшу сумарну цінність можна покласти в рюкзак (кожен предмет — не більше одного разу)?

- **Стан:** `dp[c]` — найбільша цінність при сумарній вазі не більше `c`, якщо розглянуто частину предметів.
- **Перехід:** розглядаючи предмет `i`, для кожної місткості `c` (від `W` донизу!) вирішуємо, класти його чи ні: `dp[c] = max(dp[c], dp[c − w[i]] + v[i])`.

Чому цикл по `c` іде **згори донизу**? Тоді `dp[c − w[i]]` ще відповідає попереднім предметам, і кожен предмет кладеться не більше одного разу. Якби цикл ішов знизу догори, предмет міг би потрапити в рюкзак кілька разів.

> [!TIP]
> Найважче в ДП — придумати стан. Тренуйся: розв’язуючи задачу, спитай себе «яку відповідь на меншу задачу мені було б корисно знати?». А ще спробуй спершу написати рекурсивний перебір — часто стан ДП видно з параметрів рекурсивної функції.

    int n, m;
    cin >> n >> m;
    vector<string> g(n);
    for (auto &row : g) cin >> row;
    vector<vector<long long>> dp(n, vector<long long>(m, 0));

            if (i > 0) dp[i][j] += dp[i - 1][j];
            if (j > 0) dp[i][j] += dp[i][j - 1];
            dp[i][j] %= MOD;
        }
    }
    cout << dp[n - 1][m - 1] << "\n";
    return 0;
}

#include <bits/stdc++.h>

## Коротко

- ДП — розв’язок через менші підзадачі, кожна з яких обчислюється один раз і зберігається в таблиці.
- Рецепт: стан (що означає `dp[i]`), перехід, база, відповідь і порядок заповнення.
- Сходинки і Фібоначчі: `dp[i] = dp[i − 1] + dp[i − 2]`; шляхи в таблиці: зверху + зліва.
- Монети, жабка — мінімум по всіх способах прийти в стан; ДП надійніше за жадібність.
- Рюкзак: цикл по місткості згори донизу, щоб предмет брався один раз.
