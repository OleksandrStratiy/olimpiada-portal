# Два вказівники

Багато задач про пари елементів і відрізки масиву «в лоб» розв’язуються двома вкладеними циклами за O(n²). Метод **двох вказівників** часто дозволяє зробити те саме за один прохід — O(n). Ідея: два індекси рухаються масивом лише вперед (або назустріч один одному), і кожен робить не більше `n` кроків.

> [!NOTE] У цьому уроці
> - пара з заданою сумою у відсортованому масиві;
> - «гусениця»: найдовший відрізок з обмеженою сумою;
> - злиття двох відсортованих масивів;
> - чому це працює за O(n).

## Пара з заданою сумою

Дано **відсортований** масив і число `S`. Чи є два елементи з сумою `S`?

Поставимо один вказівник `i` на початок, а другий `j` — на кінець масиву:

- якщо `a[i] + a[j]` **менше** за `S`, суму треба збільшити — зсуваємо `i` вправо (до більших чисел);
- якщо **більше** — зменшити: зсуваємо `j` вліво;
- якщо дорівнює — пару знайдено.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    long long S;
    cin >> n >> S;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    int i = 0, j = n - 1;
    bool found = false;
    while (i < j) {
        long long sum = a[i] + a[j];
        if (sum == S) { found = true; break; }
        if (sum < S) i++;
        else j--;
    }
    cout << (found ? "YES" : "NO") << "\n";
    return 0;
}
```

```input
6 13
1 3 4 6 9 11
```

```output
YES
```

(4 + 9 = 13.) Чому ми нічого не пропускаємо? Якщо `a[i] + a[j] < S`, то `a[i]` у парі з **будь-яким** елементом лівіше від `j` дасть ще меншу суму — отже, з `a[i]` пари немає, і його можна відкинути. Аналогічно для `j`. На кожному кроці один із вказівників зсувається, тож кроків не більше `n`.

> [!IMPORTANT]
> Метод працює лише для **відсортованого** масиву. Якщо масив не відсортовано — спершу `sort` (тоді разом вийде O(n log n)).

## «Гусениця»: найдовший відрізок

Дано масив **невід’ємних** чисел і число `S`. Знайди найдовший відрізок (кілька елементів поспіль), сума якого не перевищує `S`.

Уяви гусеницю, що повзе масивом. Її голова `r` щокроку просувається на один елемент вперед. Якщо гусениця стала «заважкою» (сума більша за `S`), вона підтягує хвіст `l`, доки знову не стане легкою.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    long long S;
    cin >> n >> S;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    long long sum = 0;
    int l = 0, best = 0;
    for (int r = 0; r < n; r++) {
        sum += a[r];               // голова просувається вперед
        while (sum > S) {          // заважко — підтягуємо хвіст
            sum -= a[l];
            l++;
        }
        best = max(best, r - l + 1);
    }
    cout << best << "\n";
    return 0;
}
```

```input
7 10
4 2 3 6 1 1 5
```

```output
3
```

Відрізки довжини 3 із сумою ≤ 10: `4 2 3` (9), `6 1 1` (8), `1 1 5` (7). Відрізка довжини 4 немає.

Хоча тут є вкладений цикл `while`, складність — O(n): `l` і `r` рухаються лише вперед і кожен проходить масив не більше одного разу. Отже, загалом не більше 2n кроків.

> [!WARNING]
> «Гусениця» спирається на те, що числа невід’ємні: подовження відрізка не зменшує суму, а скорочення не збільшує. Для масивів з від’ємними числами цей метод не працює — там допомагають префіксні суми.

## Злиття двох відсортованих масивів

Дано два відсортовані масиви. Треба отримати один відсортований масив з усіх елементів. Вказівник `i` йде першим масивом, `j` — другим; щокроку беремо менший з `a[i]` і `b[j]`:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> a = {1, 4, 7, 9}, b = {2, 3, 8};
    vector<int> c;
    int i = 0, j = 0;
    while (i < (int)a.size() || j < (int)b.size()) {
        if (j == (int)b.size() || (i < (int)a.size() && a[i] <= b[j])) c.push_back(a[i++]);
        else c.push_back(b[j++]);
    }
    for (int x : c) cout << x << " ";
    cout << "\n";
    return 0;
}
```

```output
1 2 3 4 7 8 9
```

Запис `a[i++]` означає: взяти `a[i]`, а потім збільшити `i` на 1. Злиття працює за O(n + m) — швидше, ніж склеїти масиви і відсортувати.

## Перевір себе

```quiz
? Масив відсортовано, `a[i] + a[j]` більше за потрібну суму. Що робити?
- Зсунути `i` вправо
+ Зсунути `j` вліво
- Зупинитися: пари немає
: Щоб зменшити суму, беремо менший правий елемент.

? Чому «гусениця» працює за O(n), хоча в ній є вкладений `while`?
+ Бо обидва вказівники рухаються лише вперед і кожен проходить масив один раз
- Бо `while` завжди виконується один раз
- Вона працює за O(n²)
: Сумарна кількість кроків обох вказівників не перевищує 2n.

? Для яких масивів підходить «гусениця» для пошуку відрізка з сумою не більше S?
- Для будь-яких
+ Лише для масивів з невід’ємних чисел
- Лише для відсортованих
: З від’ємними числами додавання елемента може зменшити суму, і логіка «підтягни хвіст» ламається.

? Яка складність злиття двох відсортованих масивів довжин n і m?
- O(n · m)
+ O(n + m)
- O((n + m) log (n + m))
: Кожен крок забирає один елемент, усього n + m кроків.
```

id: close-pairs
title: Близькі пари
level: 2
=== statement
Дано `n` чисел і число `d`. Скільки є пар (з різними номерами), у яких числа відрізняються не більше ніж на `d`? Пари (i, j) і (j, i) вважаються однаковими.
=== input
У першому рядку — числа `n` і `d` (1 ≤ n ≤ 10⁵, 0 ≤ d ≤ 10⁹). У другому — `n` цілих чисел, кожне за модулем не більше 10⁹.
=== output
Кількість пар.
=== example
5 2
1 10 3 2 7
---
3
=== test
1 5
1
---
0
=== test
4 0
5 5 5 5
---
6
=== test
3 1000000000
-1000000000 0 1000000000
---
2
=== hint
Відсортуй масив. Для кожного `j` знайди найменше `i`, для якого `a[j] − a[i] ≤ d`: усі елементи з `i` по `j − 1` утворюють пару з `a[j]`. Зі зростанням `j` межа `i` теж лише зсувається вправо.
=== hint
Відповідь може сягати 5·10⁹ — потрібен `long long`.
=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    long long d;
    cin >> n >> d;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    sort(a.begin(), a.end());
    long long pairs = 0;
    int i = 0;
    for (int j = 0; j < n; j++) {
        while (a[j] - a[i] > d) i++;
        pairs += j - i;
    }
    cout << pairs << "\n";
    return 0;
}
```

=== hint
Гусениця навпаки: просувай голову, доки сума менша за `S`; щойно сума стала ≥ S, запам’ятай довжину і підтягуй хвіст, поки сума залишається ≥ S.
=== solution
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    long long S;
    cin >> n >> S;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    long long sum = 0;
    int l = 0, best = 0;
    for (int r = 0; r < n; r++) {
        sum += a[r];
        while (sum >= S) {
            if (best == 0 || r - l + 1 < best) best = r - l + 1;
            sum -= a[l];
            l++;
        }
    }
    cout << best << "\n";
    return 0;
}
```

## Коротко

- Два вказівники перетворюють перебір пар чи відрізків з O(n²) на O(n), бо кожен вказівник рухається лише в один бік.
- Пара з сумою у відсортованому масиві: вказівники з двох кінців назустріч.
- «Гусениця» для відрізків з невід’ємних чисел: голова йде вперед, хвіст підтягується.
- Злиття відсортованих масивів — O(n + m).
